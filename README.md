# 暗黑地牢 I 测试修改器

适配 Steam 64 位 Build 28063（Steam Build ID 25463639）。版本 0.3.0，包含 14 项修改功能、SL 整槽回档、自动备份，以及按现实日期和游戏周数选择回档点。

[下载 Windows 便携测试版](https://github.com/hydrangeia/darkest-dungeon-trainer/releases/tag/v0.3.0)。完整解压后运行 `暗黑地牢测试修改器.exe`，无需安装 Python。

## 开始使用

1. 解压整个压缩包，保留 `app`、`runtime`、`licenses` 与启动器的相对位置。
2. 在 Steam 启动选项中选择 **Win 64-bit version**，进入常规战役。
3. 运行 `暗黑地牢测试修改器.exe`，点击“连接游戏”。无需安装 Python。
4. 勾选功能；数值项目可先输入数值再开启。再次取消勾选会停止该功能。
5. 结束测试时点击“关闭全部 / 断开”或正常关闭修改器，以恢复原游戏指令和原始速度。

连接前会核对完整程序 SHA-256 和修改位置的原始指令，再备份自动识别的存档。新版本或其他程序版本会拒绝连接。备份位于 `app/backups`；诊断文件可由界面导出。

如果连接失败，请先确认 Steam 选择了 **Win 64-bit version**。菜单里的版本号无法区分 32/64 位程序。重新连接后导出的诊断会附实际程序信息；也可双击 `游戏程序检查.cmd`，只读采集正在运行的游戏程序路径、位数和哈希，报告保存在 `app` 下。这个检查不会读取或修改游戏内存。

## SL 回档

1. 正常退出游戏，让自动存档和 Steam 同步完成。
2. 打开“存档 / SL 回档”，点击“扫描存档”，选中要测试的存档槽。
3. 输入回档点名称，例如“进地牢前”，点击“保存回档点”。
4. 启动游戏进行测试。想回档时，正常退出游戏，等同步结束。
5. 在修改器中选择之前的回档点，点击“恢复所选回档点”，再启动游戏。

SL 恢复整个存档槽，包括英雄、资源、城镇和地牢进度；回档点之后新增的存档文件也会移除。每次恢复前会自动保存当前进度，选择这个“回档前自动保留”的回档点即可撤销。名称、时间和历史记录会保留到下次打开修改器，可点击“刷新回档点”重新读取。

回档点放在 `app/backups/checkpoints`。升级修改器时，请保留旧版 `app/backups` 文件夹和 `app/autosave_settings.json`（如果存在），复制到新版同一位置。

## 自动备份与日期选择

在存档页选择存档槽，开启“自动创建回档点”，设置检查间隔（默认 10 分钟）。修改器保持打开时，会定时复制已经写到磁盘的进度；检测到存档仍在写入，就跳过并稍后重试。没有新进度时不重复建点，游戏退出后会补存最终进度。开关、间隔和存档槽会保存到本地设置中。

自动备份复制游戏的落盘存档，不会强制游戏立刻保存内存中的状态。自动回档点与手动点都会保留，程序不自动清理历史。

可以输入现实的 N 天前，选择目标时间之前最近的回档点；也可以按游戏“第 N 周”选择该周最近的回档点。选择后会展示时间、周数和文件数，再点击“恢复所选回档点”。没有对应历史时会提示无匹配记录，旧点读不到周数时显示“周数未知”。

游戏周数来自回档点中 `persist.campaign_log.json` 的 `base_root.total_weeks`。游戏运行时可以自动备份，恢复时仍需完全退出。

## 功能与快捷键

热键仅在已连接的游戏窗口处于前台时生效，切出游戏后自动释放。请开启 Num Lock。键被其他程序占用时，界面会显示冲突；仍可点击控件。

| 快捷键 | 功能 | 说明 |
| --- | --- | --- |
| Num 1 | 无限生命 | 英雄收到的正数伤害归零；不会复活已死亡英雄 |
| Num 2 | 压力清零 | 清零当前英雄压力并阻止正数压力增加；已有折磨等状态不额外移除 |
| Num 3 | 最大亮度 | 地牢火把亮度固定为 100 |
| Num 4 | 物品不减 | 地牢背包物品使用时不扣数量 |
| Num 5 | 金币 | 开启期间固定为输入值，默认 9999999 |
| Num 6 | 半身像 | 默认 999 |
| Num 7 | 肖像 | 默认 999 |
| Num 8 | 地契 | 默认 999 |
| Num 9 | 徽章 | 默认 999 |
| Num 0 | 超级伤害 / 一击必杀 | 敌人收到的正数伤害放大到致命数值 |
| Num . | 伤害倍率 | 敌人收到的正数伤害乘以倍率，默认 2.0，范围 0.1～100 |
| Num + | 防御倍率 | 英雄收到的正数伤害除以倍率，默认 2.0，范围 0.1～100 |
| Ctrl + Num 1 | 商店无限库存 | 补给商店与饰品商店商品扣除时保持数量 |
| Ctrl + Num 2 | 游戏速度 | 默认 2.5，范围 0.1～10；关闭时恢复开启前速度 |
| Ctrl + Shift + Home | 暂停 / 恢复热键 | 只暂停热键，已开启的功能继续生效 |

无限生命优先于防御倍率，一击必杀优先于伤害倍率。治疗数值不受伤害修改影响。关闭功能会停止后续修改；已改变的资源、压力与游戏进度仍按游戏当前状态保留。

## 存档编辑

存档页可在游戏完全退出后修改五种资源并清零英雄压力。“备份恢复”用于撤销本工具的数值编辑，会检查编辑之后是否产生新进度。需要恢复游戏进度时，请使用上面的“SL 回档”。

## 从源码运行和测试

需要 Windows x64、Python 3.13（含 Tk）。

```powershell
python -m pip install -r requirements-dev.txt
python trainer_ui.py
python -B -m unittest discover -s tests -v
python -B trainer_ui.py --self-test
```

测试使用合成存档。库存原生测试需要本机匹配的游戏程序，可用环境变量 `DD_GAME_EXE` 指定路径；缺少程序时该组测试会跳过。

`package_runtime.py` 用于裁剪 Python/Tk 运行库并编译 C# 启动器，当前便携包按 Windows Conda 环境验证，可通过 `--python-root` 指定环境根目录。`release_package.py` 收集应用代码、说明和运行库生成便携 ZIP。源代码使用 MIT 许可证；便携运行库的第三方许可证随包保留在 `licenses` 中。
